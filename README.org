#+title: Furball

Furball browses Datadog monitors and logs in Emacs. Its landing page takes
inspiration from [[https://github.com/wandersoncferreira/agent-shell-dashboard][agent-shell-dashboard]]: compact saved-view sections, status badges,
keyboard navigation, and drill-down buffers.

* Setup

Requires Emacs 29.1 or later, Transient 0.7 or later, and [[https://github.com/DataDog/pup][Datadog Pup]]. Install Pup using its
Homebrew tap:

#+begin_src sh
brew tap datadog-labs/pack
brew install datadog-labs/pack/pup
#+end_src

Authenticate through Pup, for example with browser-based OAuth:

#+begin_src sh
DD_SITE=us5.datadoghq.com pup auth login
#+end_src

Pup also supports =DD_API_KEY= and =DD_APP_KEY= in its environment. When
using those credentials, make them available in Emacs's environment.
Pup owns authentication and credential storage; Furball passes the selected
site as =DD_SITE= to each child process. See [[https://github.com/DataDog/pup#authentication][Pup authentication]] for details.

Add this checkout to =load-path= and load Furball:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/furball")
(require 'furball)
(setq furball-site "us5.datadoghq.com")
#+end_src

Pup must be on Emacs's =exec-path=, or set =furball-pup-command= to its
absolute executable path. =DD_SITE= supplies Furball's initial default site.
=furball-pup-timeout= limits each request to 60 seconds by default.

Access requires =monitors_read= and =logs_read_data= permissions
and access to the data being queried. See Datadog's [[https://docs.datadoghq.com/api/latest/monitors/monitors-search/][monitor search]] and
[[https://docs.datadoghq.com/api/latest/logs/search-logs/][log search]] documentation. Furball only reads Datadog data, including when
it uses the log-search POST endpoint.

* Saved landing views

=M-x furball= opens the ordered views in =furball-landing-page=. Customize
that variable or set it using alists:

#+begin_src emacs-lisp
(setq furball-landing-page
      '(((:name . "Sidekick monitors")
         (:kind . monitors)
         (:query . "tag:\"component:sidekick\""))
        ((:name . "Sidekick task failures")
         (:kind . logs)
         (:query . "service:prosite-celery-titan-messaging \"Sidekick task failed\" env:prod")
         (:time-range . "1h"))))
#+end_src

Each view has =:name=, =:kind= (=monitors= or =logs=), and =:query=.
Optional =:site= overrides the configured site. Log views accept
=:time-range=, such as =15m=, =1h=, or =2d=; the default is one hour.
Editing a running view does not modify its saved customization.

* Traceback source navigation

Use =? c= on a log row or in its full-log buffer to open a read-only
=compilation-mode= buffer in the same window. Emacs recognizes supported
stack-frame formats and provides source navigation. If no separate stack
field exists, the log message is used.

Saved views can supply either or both keys below. They follow monitor
rows through monitor details, matching logs, and full-log buffers:

#+begin_src emacs-lisp
(:directory-abbrev-alist . (("^/app/" . "/Users/cate/dev/prosite/")))
(:project-directory-id-fn . my/sidekick-project-directory)

(defun my/sidekick-project-directory (buffer)
  "Return the source checkout for the Furball BUFFER."
  (ignore buffer)
  (expand-file-name "~/dev/prosite/"))
#+end_src

The callback receives the originating Furball buffer and must return an
existing absolute directory. It can inspect that buffer to choose a
monorepo subdirectory. Without it, the source buffer's =default-directory=
is used. Relative source paths resolve against this base directory.

The abbreviation alist uses =(REGEXP . REPLACEMENT)= entries. Furball sets
it buffer-locally and translates the entries to compilation's
=compilation-transform-file-match-alist= for source-file lookup. This allows
container path prefixes to map to local paths without rewriting the displayed
traceback. Compilation parsing determines which frame formats are navigable;
this does not perform general language detection.

* Log view functions

Add =:log-view-functions= to a saved log view to expose your own functions:

#+begin_src emacs-lisp
((:name . "Sidekick task failures")
 (:kind . logs)
 (:query . "service:prosite-celery-titan-messaging env:prod")
 (:log-view-functions . (my/sidekick-investigate-log my/copy-log-context)))
#+end_src

Use =? x= in that log view or its full-log buffer (or on a dashboard log
preview). Functions receive one argument: the originating Furball buffer
object. Full-log buffers contain the complete retrieved message, traceback,
and JSON, so open a log before invoking a function that needs that context.
The callback can use =with-current-buffer= and =buffer-substring-no-properties=
to read it, then open a project or start an agent-shell session.

The submenu assigns =1= through =9=, then =a= through =z=, in configuration
order, using function names as labels. Up to 35 defined function symbols are
supported. =C-g= cancels; letter keys, including =q=, belong to callbacks.
Bindings only apply inside this submenu and do not override Evil navigation.

* Browse and investigate

Interactive =M-x furball= opens the dashboard, ready for navigation.
Press =?= in results or log details, or =C-c ?= in the query editor, for
commands relevant to that view. Long results and query drafts stay in
their buffers while menus provide actions and editable arguments.

The saved-view selector opens any configured view. The log-search menu
lets you set a query, relative window, and Datadog site before fetching.
Search, URL, time, and status menus apply their arguments with =RET=;
opening or cancelling a menu leaves the current scope unchanged. Within
menus, =q= closes the menu; =Q= quits the view where offered. Direct buffer
shortcuts remain available when no menu is active:

| Key | Action |
|-----+--------|
| =RET= / =o= | Open selected view, monitor, group logs, or full log record |
| =TAB= | Expand/collapse the selected log inline |
| =n= | Next selectable row |
| =p= / =S-TAB= | Previous selectable row |
| =e= | Edit the current query in a separate buffer |
| =g= | Refresh |
| =m= | Fetch the next page |
| =s= | Open the monitor status menu |
| =t= | Open the relative time-window menu |
| =l= | Open the log-search menu |
| =u= | Open the URL-import menu |
| =b= | Open the current view in Datadog |
| =^= | Return to the landing page |
| =q= | Quit the window |

From the landing page, select an /Open/ row to edit that saved view's query.
In the query buffer, =C-c C-c= runs the query, =M-TAB= completes at point,
and =C-c C-k= returns. Retrieved log buffers and full log records are
read-only. Completion offers built-in syntax, observed nested custom fields
and values, and quoted monitor tag values. It does not fetch Datadog's
complete facet catalog.

=RET= or =o= on a log row opens a read-only detail buffer with the full
message, multiline =error.stack= (nested or flat) and =exc_info= tracebacks,
and raw JSON below. Identical traces appear once; lines wrap and Furball
does not truncate them. If no separate traceback was returned, the buffer
says so and shows the message. This displays retrieved fields only; it
cannot recover server-side truncation. =q= closes the view, including in
Evil normal and motion states.

When Evil is available, Furball loads its optional Evil integration
without changing the ordinary Emacs bindings. Results start in normal
state, with application commands available in normal and motion states;
=j= and =k= move between selectable rows; =h= and =l= move left and right.
Use =L= for log search in Evil and in the Transient menu.
View-menu actions also work directly in normal and motion states: =x= opens
configured functions, =c= opens a traceback, and =v= selects a saved view.
In the query editor, =r= runs the query and =c= completes at point in normal
state; insert-state typing is unchanged. Query buffers start in insert
state. =C-c C-c= and =C-c C-k= work in normal, insert, and visual states.

Open an ALERT or WARN monitor, then select a group to show matching logs
alongside its current configuration. Automatic drill-down supports count log
monitors. It adds the selected group's tags to the search, preserving =@=
attribute prefixes from the expression's grouping. The best-effort window
uses the group's last recorded trigger; WARN groups use the current time
because the exact warning transition is unavailable. The current monitor
evaluation delay is subtracted before deriving the window.
The search uses the current monitor configuration, so these are matching
logs, not a reconstruction of historical evaluation evidence.
The notification template appears in a read-only Org-style Markdown source
block, preserving Datadog placeholders; it is not rendered as rich Markdown.

=M-x furball-logs= also accepts a count monitor expression:

#+begin_example
logs("service:prosite-celery-titan-messaging \"Sidekick task failed\" env:prod").index("*").rollup("count").by("env,@error.kind").last("1h") > 1
#+end_example

Furball extracts the search, indexes, and window and displays matching log
records. It retains the grouping and threshold as context; it does not
compute grouped aggregates or evaluate the alert condition. Other rollups
and monitor expression forms are not supported.

=M-x furball-open-url= imports HTTPS Datadog =/logs?= links with valid
=from_ts= and =to_ts= timestamps. It preserves the exact fixed window,
search, sort order, storage tier, and monitor/event identifiers. A linked
monitor opens alongside the logs. Datadog visualization and aggregation
options are not reproduced. Use =t= and apply to switch to a recent window.
Pagination keeps the same window; refreshing a relative view advances it.
Editing an expression's =.last= duration recalculates the start while keeping
a fixed historical end; applying the =t= menu switches to a latest window.

Results show fetch time and errors. Previous results remain available during
refresh or a failed request; if the query changed, they are labeled as
belonging to the previous query. Datadog warnings and timeouts mark a result
as partial. Pup runs asynchronously; process failures, invalid JSON, and
request timeouts appear as fetch errors. Timeout cancellation terminates
the request process and retains existing results.

* Development

Tests cover query and buffer behavior with mocked responses, and exercise
the asynchronous transport with local subprocess fixtures. They require no
live credentials and do not establish live Datadog connectivity.
With an Emacs server running, load and run the tests using =emacsclient=:

#+begin_src sh
emacsclient --eval '(progn (add-to-list (quote load-path) "/path/to/furball") (load "/path/to/furball/tests/furball-tests.el") (load "/path/to/furball/tests/furball-transient-tests.el") (ert-run-tests-interactively "^furball-"))'
#+end_src

If Evil is installed and available on =load-path=, also load
=tests/furball-evil-tests.el= before running the same ERT selector:

#+begin_src sh
emacsclient --eval '(load "/path/to/furball/tests/furball-evil-tests.el")'
#+end_src

Inspect the ERT results buffer in Emacs. Do not use
=ert-run-tests-batch-and-exit= against the shared server.

A Makefile wraps the same checks in a standalone batch Emacs, installing
=elisp-lint= and its dependencies into a local =.sandbox= directory on
first use:

#+begin_src sh
make format   # reindent sources and tests in place
make lint     # byte-compile, checkdoc, package-lint, indentation, whitespace
make test     # run the ERT suite
make check    # lint and test
#+end_src

The =pre-commit= hook in =.githooks= runs =make lint= whenever staged
changes include Emacs Lisp files.

* Commit messages

Enable the repository's Conventional Commits hook after cloning:

#+begin_src sh
git config --local core.hooksPath .githooks
#+end_src

The =commit-msg= hook validates =type(scope): description= headers (scope is
optional). Use =!= before the colon for breaking changes. Accepted types are
=feat=, =fix=, =docs=, =style=, =refactor=, =perf=, =test=, =build=, =ci=,
=chore=, and =revert=. Run =sh tests/commit-msg-hook.sh= to check the validator.
